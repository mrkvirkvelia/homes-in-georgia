# Тестовый сервер

Отдельная копия CRM, где пробуем новые функции до того, как они попадут в рабочую CRM. Ссылкой можно делиться
(например, с Давидом), чтобы согласовать.

- **Адрес:** https://hig-test.91-99-162-108.sslip.io
- **Вход:** логин и пароль (Telegram там выключен). Логины: `irakli`, `david` (суперадмины), `nino` (оператор),
  `georgiy`, `levan` (агенты). Пароль один на всех, его печатает в конце `deploy/test-push.sh`.
- Вверху каждой страницы жёлтая плашка **«ТЕСТ · выдуманные данные»**: так её не спутать с рабочей CRM.

## Чем отличается от рабочей CRM

| | Рабочая (admin.hge.ge) | Тестовая |
|---|---|---|
| Данные | настоящие | выдуманные (демо: агенты, заявки, объекты, сделки) |
| Telegram | бот, канал, уведомления | полностью отключён: никому ничего не уходит; «Опубликовать» отмечает объект опубликованным без поста в канал |
| Код | ветка `main` | то, что выложено последним `test-push.sh` (любая ветка, даже с незакоммиченными правками) |
| Фото | S3 | диск тестового сервера |

Отправка слотов клиентам, userbot оператора, Google Drive, публикация в канал на тестовом сервере не работают (там
нет Telegram и ключей). Всё остальное — как в рабочей.

## Выложить новую версию (с Mac)

```bash
cd ~/hge/homes-in-georgia
bash deploy/test-push.sh            # обновить, данные остаются
bash deploy/test-push.sh --reset    # обновить и начать с чистых демо-данных
```

Скрипт копирует на сервер файлы проекта (как в git, без `.env`, без настоящих данных агентства), собирает и
перезапускает тестовую копию (несколько минут), создаёт демо-данные при первом запуске и печатает адрес и пароль.
Что сейчас выложено: `ssh root@91.99.162.108 cat /opt/hig-test/app/.deployed`.

## Как устроено на сервере

- Папка `/opt/hig-test/app`, ключи в `/opt/hig-test/app/.env.test` (свои, не от рабочей CRM; создаются при первом запуске).
- Docker compose проект `hig-test` (`deploy/docker-compose.test.yml`): только `db`, `api`, `worker`; свои тома
  `hig-test_pg`, `hig-test_media`. API на `127.0.0.1:8100`.
- Caddy: блок `hig-test.91-99-162-108.sslip.io` в `/opt/caddy/Caddyfile` (дописан в конец, `noindex`).
- Признак тестового режима: `TEST_MODE=1` (плашка, вход по паролю, публикация без Telegram), `TG_API_BASE` указывает в
  никуда. Аккаунты и пароль: `backend/app/test_accounts.py` (отказывается работать без `TEST_MODE`).
- Рабочая CRM (`/opt/homes-in-georgia`, проект `deploy`) этим не затрагивается.

Удалить тестовую копию целиком: `cd /opt/hig-test/app && docker compose -p hig-test -f deploy/docker-compose.test.yml
--env-file .env.test down -v`, убрать блок из Caddyfile, `docker exec caddy caddy reload --config /etc/caddy/Caddyfile`.

## Что проверить сейчас

**Декларации RS.ge** (ветка `tax-declarations`; агент с ИП сам вносит сумму из банковской выписки и сам подаёт на rs.ge):
1. Войти как `georgiy` (агент) → «Кабинет» → вкладка «Декларации». Если просит номер ИП: заполнить профиль на вкладке
   «Обзор» (11 цифр), вернуться.
2. В карточке прошлого месяца ввести сумму поступлений, например `4520,50` → сразу виден налог 1% (45,21 ₾) →
   «Сохранить». Статус «Сумма внесена».
3. Поставить галочку «Я подал декларацию на rs.ge» → «Сохранить». Статус «Подана».
4. Внизу история за 12 месяцев: «Изменить» у любого месяца.
5. Войти как `nino` (оператор) → «Кабинет» → «Декларации»: сводка по команде за месяц (с ИП, подали, внесли, не начали),
   клик по человеку открывает его декларации только для просмотра.
6. Напоминания в Telegram (1, 10 и 14 числа в 10:00) на тестовом сервере не приходят: Telegram там выключен.
